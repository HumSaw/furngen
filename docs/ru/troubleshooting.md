[English](../en/troubleshooting.md) &middot; Русский

---

## Диагностика в первую очередь

Откройте MAXScript Listener (`F11`) и посмотрите строки загрузки:

```
FurnGen Core 1.0.0 loaded
FurnGen Materials loaded (Corona available: true, Corona active: false)
FurnGen 1.0.0 ready. Recommended System Units: Centimeters.
```

Вторая строка отвечает на самый частый вопрос — какой стек материалов будет
использован. Все сообщения инструмента начинаются с `FurnGen`, поэтому их легко
отфильтровать среди вывода самого Max:

| Префикс | Источник |
| --- | --- |
| `FurnGen QA:` | Автопроверка результата |
| `FurnGen MTL WARN:` | Материал не принял цвет, выполнен откат |
| `FurnGen ERROR:` | Модуль не найден при загрузке |
| `FurnGen:` | Прочие сообщения, например пропуск регистрации макроса |

## Модели серые или без материалов

### Причина 1: Corona установлена, но не активна

`FurnGen Materials loaded (Corona available: true, Corona active: false)`

Corona-материалы рендерятся серыми или чёрными под другим движком.

**Решение.** Либо назначьте Corona активным рендером
(`Render Setup → Renderer → Corona`), либо ничего не делайте: FurnGen сам
соберёт `PhysicalMaterial`, который корректно работает в Scanline и Arnold.
Важно перезапустить `FurnGen.ms` после смены рендера — стек определяется
в момент создания материала.

### Причина 2: вьюпорт в режиме Object Color

Нажмите `F3` / переключите Shading на **Default Shading**. FurnGen дополнительно
проставляет `wirecolor` каждой ноды из цвета материала, поэтому даже в этом
режиме модель не должна быть полностью серой.

### Причина 3: цвет не записался

В Listener есть строка:

```
FurnGen MTL WARN: no colour property on 'FurnGen_Fabric', falling back to Standard
```

Это не ошибка: материал автоматически заменён на `StandardMaterial`, модель
пригодна к рендеру. Сообщение полезно приложить к issue — оно указывает на
несовместимость имён свойств в вашей версии Max.

## `-- Unknown system exception` или ошибки при загрузке

### Модули не найдены

Появляется диалог `FurnGen could not start: N module(s) missing.`, а в Listener
перечислены конкретные файлы:

```
FurnGen ERROR: module not found: C:\...\modules\core.ms
```

`FurnGen.ms` ищет папку `modules` рядом с собой. Проверьте структуру:

```
FurnGen/
├── FurnGen.ms
└── modules/*.ms
```

Запуск отдельного модуля напрямую не сработает — только `FurnGen.ms`.

### Файл заблокирован Windows

Если архив скачан из интернета, Windows может блокировать содержимое.
Правый клик по ZIP → **Properties** → отметьте **Unblock** → распакуйте заново.

## Геометрия рваная или вывернутая

В версии 1.0.0 fillet ограничивается автоматически внутри `fgSoftBlock`
и `fgCushion`. Если проблема всё же появилась:

1. Проверьте системные единицы — сантиметры.
2. Уменьшите **Softness** до `0.4` и ниже.
3. Приложите к issue `Seed`, категорию, тип и стиль: с этими данными
   результат воспроизводится точно.

## Модель гигантская или микроскопическая

Строка состояния показывает `CHECKED: ...`, а в Listener появляется:

```
FurnGen QA: WARN: system units are Inches, Centimeters recommended
```

`Customize → Units Setup → System Unit Setup → 1 Unit = 1.0 Centimeters`.
Уже созданные модели придётся сгенерировать заново — существующая геометрия
не пересчитывается.

## Панель не открывается

Скрипт загрузился, но окна нет:

```maxscript
fgOpenUI()
```

Введите эту строку в Listener. Если панель появилась — предыдущий floater
остался в памяти; повторный запуск `FurnGen.ms` закрывает старое окно
автоматически.

---

## Один и тот же Seed даёт разный результат

Проверьте, что совпадают **все** параметры: категория, тип, стиль, ткань,
габариты, softness и уровень качества. Уровень качества меняет число
сегментов и количество проходов Noise, поэтому Draft и Production при
одном Seed дают близкие, но не идентичные модели — так и задумано.

---

## Генерация прервалась с ошибкой

```
Error: -- Unable to convert: undefined to type: Float
```

Такое сообщение в строке состояния означает, что сборка упала, но
частичная геометрия уже откачена через `max undo` — сцена чистая.
Полный текст исключения есть в Listener; приложите его к issue вместе
с версией Max, активным рендером и параметрами панели.

---

## Ковёр или зеркало «утопают» в полу

Оба предмета сознательно тонкие и лежат на нулевой отметке. Если в вашей
сцене пол не на `Z = 0`, сдвиньте группу вручную — FurnGen всегда строит
от нулевого уровня пола.

---

## Куда сообщать о проблеме

Приложите к issue:

- версию 3ds Max и активный рендер
- три строки загрузки из Listener
- полный текст ошибки, если есть
- категорию, тип, стиль, `Seed` и уровень качества

Шаблон бага в репозитории запрашивает ровно эти поля.
